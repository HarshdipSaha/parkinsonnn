# Effort 008 — requirements delta (vs `aidlc-docs/inception/`)

| Id | Kind | Requirement | Evidence / acceptance |
|---|---|---|---|
| R25 | NEW | A zip is never written that exceeds `--max-mb`. When `DROP_ORDER` is exhausted and the zip is still over the ceiling, the build **exits non-zero** instead of writing it. | `scripts/build_master_v3.py` raises `SystemExit`; `tests/test_run9.py::test_build_master_v3_refuses_an_oversized_zip`. |
| R26 | CHANGED | The container check verifies **every** arm in the manifest, not only the torch arms that print `checkpoints used N/N`. A run is rejected if any manifest arm produced no output, if a `ladder:` / `arm … failed` / `checkpoint failed` / `Traceback` line appears, or if the manifest sets `typ`. | `scripts/local_e2e_v3.py`; `tests/test_run9.py::test_local_e2e_catches_a_silent_arm`. Rule basis: submissions must not log test-set statistics (`DAT_PARKINSONS_CHALLENGE.md`:86). |
| R27 | NEW | The prior mix is chosen against its **downside**, not only the nested curve. The sweep reports, per λ, the nested loss, the worst-case nats on a confident miss, and the break-even count of confidently-wrong scans that erases that λ's gain over λ = 0.01. | `scripts/sweep_calibration.py`; ADR 0006; `tests/test_run9.py::test_worst_case_nats_prices_the_clip`. |
| R28 | NEW | No leaderboard movement is attributed to a calibration constant without first confirming both submissions ran the same arms. A λ-only change is bounded at 0.0055 nats and is worth 0.0020 on the real pool; anything larger came from the ensemble changing. | `tests/test_run9.py::test_lambda_only_gain_is_bounded`, `::test_pool_reproduces_the_shipped_master_v2_number`; ADR 0006. |
| R29 | CHANGED | Slot policy for the final submission: the slot opens Sept 14 03:38 UTC but is spent **as late as is safe** (freeze Sept 16 12:00, smoke 14:00, upload ~16:00). A candidate replaces the banked zip only if its gate table beats **0.2266** by ≥ 0.002 and it fits the size envelope with no drop line. | Plan §7; `RESULTS_LOG.md` records the decision and the id. |
| R30 | NEW | Every public or smoke score recorded carries a DrivenData submission id that exists on the submissions page, together with the per-arm `checkpoints used N/N` read from `View log`. | `RESULTS_LOG.md`; plan Step 1. Reinstates the rule in `HANDOFF.md`:126 after it lapsed for slots 1 and 2. |
